## 0. 三十秒看懂

1. **界面照图做**：20 屏逐屏对应一张 PNG（§1 总表）。分区、每块面板的标题、图上的字段与数值、按钮文字，**逐字对齐**。
2. **流程照图走**：每一屏的入口、出口、每个按钮点了去哪一屏，见 §4 出/入口表。**不许自己发明屏**（现有实现里"把两屏合成一屏""多出来的按钮"都要按本文件改回来）。
3. **图是权威，但图有错**：已知图上文字描述与 `界面需求初稿` / 文字稿冲突若干处（§6 勘误登记）。**先按图做**，冲突逐条登记待你拍板。
4. **数据不许编**：屏上的数字（覆盖率、成功率、威胁等级、集群数、目标数）一律来自引擎与规则包；拿不到就留空并写明原因（沿用工程既有纪律）。
5. **能点才算数**：本文件每屏都列了"MUST 可点控件 → 点了发生什么 → 去哪一屏"，验收就是逐条点一遍（§8）。

## 8. 验收（本文件怎么算落地）

### 8.1 逐屏元素断言（每屏 MUST 全绿）
对每一屏：
1. **截图对照**：`chrome --headless` 1280×800（或按 §1 基准 1536×1024）截图 → 人工与参考图并排比对（落 `docs/screens/`）。
2. **元素存在性**（脚本可自动化）：本文件 §3 每屏列出的"MUST 元素"逐条查 DOM 文本/`data-testid`。
3. **可点性**：每个"MUST 可点控件"点击后，断言"发生的事"（事件/回执/落屏）与 §3 一致。

### 8.2 流程断言（一条手点通路）
`node scripts\click-check.mjs` 升级为按 §4.1 的 **20 屏通路**逐步点击：每步断言当前屏名 + 关键元素 + 下一步按钮存在。**中途不许用 HTTP 推流程**（除 §4.3 表里明确的 verb）。

### 8.3 自适应断言
在 1536×1024、1672×941、1280×800 三种视口下：关键面板不裁切、不溢出、无横向滚动条。

### 8.4 个性化断言
1. 图标/点样式：改 `map-style.json` 的 `drone.useIcon=false` 与 `point.size/color` → 地图上无人机呈现为点且尺寸颜色变化；`true` 且给 `icon.url` → 呈 png。
2. 航迹：改 `track.width` / `track.dashed` → 轨迹粗细与虚实变化。
3. 地名：中文显示（数据未就绪时界面必须如实标注"底图无标注"，MUST NOT 假装有）。

### 8.5 数据真实性断言（沿用工程纪律）
屏上每个数字都能在 verb 回执里找到同名/同源字段；找不到的字段显示"—/缺失 + 原因"，且验收脚本**打印实测原值**。
