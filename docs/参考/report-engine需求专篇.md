**关键差距（本专篇主要价值）**

> 1. **渲染与业务耦合**：`createReport` 同时做取数、编号、渲染、落盘、落库**和改任务状态**——
>    这意味着"生成报告"这个动作会**顺带把任务标成已完成**（L896）。这在可复用引擎里是不可接受的：报告引擎不该改任务。
> 2. **任务用时是硬编码常量**（L897），不是算出来的。
> 3. **报告指标没有权威来源**：`mission_metrics` 表的 7 项数值今天没有计算逻辑写入。
> 4. **渲染不可替换**：HTML 拼接写死在 C++ 里，`TR-BIZ-08` 提到的 jsPDF 是另一条路，两者未统一（见 §5 D1 / §9 待确认 1）。

## 1. 定位与边界

### 1.1 定位

```
输入（只读快照）：phase-engine 时间轴 · resource-alloc 消耗 · topology 链路 · 
                 entity-ledger 目标结果 · alert-engine 告警计数 · 评估口径
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│  report-engine（C++，无 Web 框架、无 SQL）                 │
│  SCHEMA 字段装配（可溯源） → RENDER 渲染器（可替换） →        │
│  ARCHIVE 归档命名与索引                                     │
└──────────────────────┬───────────────────────────────────┘
                       │ 报告文档 + 元数据
                       ▼
   宿主：落盘 + 落库 + 静态托管 ｜ 界面：下载与历史列表
```

**一句话**：report-engine 回答"**这份报告里有哪些字段、每个字段从哪个模块取、渲染成什么格式、叫什么名字**"。
它**不推进阶段**、**不改任务状态**（现状的缺陷）、**不做界面**。

### 1.2 为什么必须是独立引擎

1. **报告字段是跨模块的汇总**：7 项指标来自 5 个不同引擎，需要一个统一的装配点与**溯源表**。
2. **渲染格式会变**：HTML / PDF / DOCX 三种诉求同时存在（初稿 §10.9 待确认格式），渲染器必须可替换。
3. **它有两个消费者**：换一套系统，字段与模板会变，但**装配 + 渲染 + 归档机制相同**。
4. **它是"演示数据不能编"的兜底**：初稿要求报告是自动生成的，字段必须可溯源到模块，而不是字符串拼接。

### 1.3 范围边界

| 做 | 不做 |
|---|---|
| 报告**字段装配**：字段清单由规则声明，每个字段声明"来源模块 + 取值口径" | 🚫 不含具体字段的中文名与业务口径（属规则包） |
| 字段**溯源**：每个数值可回答"从哪个引擎的哪次快照来的" | 🚫 不做数值计算（各引擎自算，本引擎只取） |
| 渲染器抽象（HTML / PDF / DOCX 可换），内置至少一种 | 🚫 不做落盘与静态托管（宿主） |
| 归档命名与索引（编号规则、文件名、时间戳） | 🚫 不做历史列表界面 |
| 报告的**结构版本**与可复现（同输入同输出） | 🚫 **不做任务状态推进**（现状 L896 的行为 MUST 移除） |
| 评估（毁伤/效果）口径的装配 | 🚫 不做毁伤判定（口径属评估，见 §9 待确认 3） |

### 1.4 硬约束

| 约束 | 取值 | 依据 |
|---|---|---|
| 现有接口形状 | `/reports`、`/reports/{id}`（若有）、`/assessment` 返回形状**不得破坏** | 契约 §3.7；`Api.cc` L804–821 |
| 报告编号格式 | `MT-<YYYY-MM-DD>-<4 位数字>`（现状 `"MT-" + 日期 + "-" + (nowMs % 10000)`） | `Api.cc` L833 |
| 归档路径 | `/reports/<文件名>`，由静态托管提供，**MUST 支持 Range** | 契约 §1；`Api.cc` L895 |
| 现有报告字段 | 7 项指标 + 5 项毁伤 + 任务编号/名称/区域/生成时间（**不得丢字段**） | `Api.cc` L858–885 |
| 事件与日志 | 生成后 MUST 广播 `mission.progress` 与落事件日志 `report.created`（**但不在引擎内做**，见 D2） | `Api.cc` L899–901 |
| 时间格式 | 展示 `YYYY-MM-DD HH:mm:ss`；时间戳 epoch 毫秒 | 契约 §2 |
| 语言/构建 | C++17 + CMake ≥ 3.20；仅 `nlohmann/json` | 对齐既有 C++ 模块 |

## 3. 功能需求条目

### 3.1 字段装配与溯源（RPT-SCHEMA）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| RPT-SCHEMA-01 | **MUST** 字段清单由规则声明（字段 key、显示名、单位、来源模块、取值路径、缺省行为），引擎 MUST NOT 内建字段名与单位 | 换规则即换报告结构；引擎内无 `搜索覆盖率` 字面量 | ⏳ |
| RPT-SCHEMA-02 | **MUST** 每个字段声明**来源模块与取值口径**，且在报告中可溯源 | 任取一个数值，可回答"来自哪个引擎的哪次快照" | ⏳ |
| RPT-SCHEMA-03 | **MUST** 缺省行为显式：来源缺失时 MUST 输出明确的"缺失"标记（如 `—`），**MUST NOT 用 0 或编造值** | 断掉某个引擎的输入 → 对应字段显示缺失，其它字段正常 | ⏳ |
| RPT-SCHEMA-04 | **MUST** 输入为**只读快照**：引擎 MUST NOT 读数据库、MUST NOT 调其它引擎的写接口 | 单测只传快照即可生成报告 | ⏳ |
| RPT-SCHEMA-05 | **MUST** 结构版本：报告结构有版本号并写入文档；字段增删 MUST 走版本升级 | 旧报告可按旧版本解释 | ⏳ |
| RPT-SCHEMA-06 | **SHOULD** 分组：字段可分组（任务信息 / 任务指标 / 毁伤评估 / 资源消耗 / 效能评估），分组顺序可配 | 输出分组与顺序符合规则 | ⏳ |

### 3.2 任务用时与时间口径（RPT-TIME）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| RPT-TIME-01 | **MUST** 移除硬编码用时：`duration_sec = 2*3600 + 47*60 + 36`（`Api.cc` L897）MUST 删除；用时 MUST 由任务时间轴计算 | 全仓检索 `2 * 3600` / `2*3600` 零命中；用时与 `phase-engine` 时间轴一致 | ⏳ |
| RPT-TIME-02 | **MUST** 用时口径显式：起止点是"任务创建→报告生成"还是"进入 T0→离开 T7"，可配 | 两种口径各可复算 | ⏳ |
| RPT-TIME-03 | **MUST** 分阶段耗时可选输出（供"组网时长""平均决策响应时间"等） | 分阶段时长与 `PHE-TL-03` 一致 | ⏳ |
| RPT-TIME-04 | **SHOULD** 时间格式统一走注入的格式化器，避免各处自行拼接 | 输出格式一致；换格式不改引擎逻辑 | ⏳ |

### 3.3 渲染（RPT-RENDER）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| RPT-RENDER-01 | **MUST** 渲染器为可替换接口（`IRenderer`），至少内置一种（HTML）；新增 PDF/DOCX MUST NOT 改引擎内核 | 换渲染器只改装配代码；内核零改动 | ⏳ |
| RPT-RENDER-02 | **MUST** 模板与数据分离：渲染器接收"结构 + 数据"，模板可外置 | 换模板即换版式，不改代码 | ⏳ |
| RPT-RENDER-03 | **MUST** 输出为**自包含**文档（HTML 内联样式、不依赖外网资源） | 断外网打开报告正常显示 | ⏳ |
| RPT-RENDER-04 | **MUST** 中文字体与编码正确（UTF-8），无乱码 | 中文标签与数值均正常 | ⏳ |
| RPT-RENDER-05 | **MUST** 数值格式化由规则声明（百分比保留位数、单位、千分位） | 格式可配、可复现 | ⏳ |
| RPT-RENDER-06 | **SHOULD** 打印友好：HTML 渲染器产出的文档可直接浏览器打印为 PDF（A4 适配） | 打印预览无截断 | ⏳ |
| RPT-RENDER-07 | **SHOULD** 现有 12 个字段与版式**保持兼容**（评审已见过的报告样子不能突变） | 与现状报告逐字段比对 | ⏳ |

### 3.4 归档与编号（RPT-ARCH）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| RPT-ARCH-01 | **MUST** 报告编号规则可配，**默认保持现状** `MT-<日期>-<4位>` | 默认输出与现状格式一致 | ⏳ |
| RPT-ARCH-02 | **MUST** 编号唯一性：同一时刻多次生成 MUST NOT 产生相同编号（现状用 `nowMs % 10000`，**存在碰撞风险**） | 快速连续生成 100 份，编号全不重复 | ⏳ |
| RPT-ARCH-03 | **MUST** 文件名规则可配且与编号关联；扩展名随渲染器 | 文件名可预测、可定位 | ⏳ |
| RPT-ARCH-04 | **MUST** 归档元数据输出：`{reportNo, 文件名, 生成时间, 任务 id, 结构版本}` 返回给宿主用于落库 | 宿主可据此写库；引擎不写库 | ⏳ |
| RPT-ARCH-05 | **SHOULD** 重复生成策略显式：同任务再次生成是"新报告"还是"覆盖"（可配） | 行为符合配置 | ⏳ |

### 3.5 评估装配（RPT-ASSESS）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| RPT-ASSESS-01 | **MUST** 评估字段（毁伤/效果）同样走 SCHEMA 声明与溯源，**MUST NOT 在渲染层拼装** | 换评估字段不改渲染器 | ⏳ |
| RPT-ASSESS-02 | **MUST** 目标处置结果：逐目标结果列表（目标编号 + 类型 + 处置结果）可进报告 | 与 `entity-ledger` 台账一致 | ⏳ |
| RPT-ASSESS-03 | **MUST** 口径可复算：总体毁伤率等派生值 MUST 声明计算式（由谁算、怎么算） | 派生值手算一致 | ⏳ |
| RPT-ASSESS-04 | **SHOULD** 效能评估分组：边缘自主执行率、云端策略优化次数、平均决策响应时间、命中率（初稿 §8 T7-2） | 分组可配置、可输出 | ⏳ |
| RPT-ASSESS-05 | **SHOULD** 资源消耗分组：四型消耗架数 + 任务存活率（初稿 §8 T7-2） | 与 `resource-alloc` 台账一致 | ⏳ |

### 3.6 非功能性（RPT-NFR）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| RPT-NFR-01 | **MUST** 不推进阶段、不改任务状态：现状 `Api.cc` L896 的 `UPDATE mission SET status='finished'` **MUST 从引擎移除**，改由宿主在收到"报告已生成"后自行决定 | 引擎内无任务状态写操作；生成报告本身不改变阶段 | ⏳ |
| RPT-NFR-02 | **MUST** 零外部依赖：无 Web 框架、无 SQL（落库走宿主的 `IReportSink`）；不依赖其它引擎内部 | 空环境独立构建；跨仓 import 零命中 | ⏳ |
| RPT-NFR-03 | **MUST** 确定性：同输入快照 MUST 产出逐字节一致的文档（时间戳可注入） | 注入固定时钟，两次生成字节一致 | ⏳ |
| RPT-NFR-04 | **MUST** 独立交付：独立构建、独立示例、独立测试、独立验收脚本（退出码 0/1） | 空环境 clone → 一条命令构建 → 一条命令验收 | ⏳ |
| RPT-NFR-05 | **SHOULD** 性能：单份报告生成（≤ 100 字段）≤ 50 ms | 实测达标 | ⏳ |
| RPT-NFR-06 | **SHOULD** 大文档安全：字段数或行数超限时 MUST NOT 无界增长内存 | 超大输入下受控并如实上报 | ⏳ |

## 4. 引擎与规则的划分（policies）

| 属引擎（可复用） | 属规则（`policies/mapapp`，项目专属） |
|---|---|
| 字段装配框架与**溯源**机制 | **字段清单**：7 项指标 + 5 项毁伤 + 任务 4 项 + 分组与顺序 |
| 缺失值语义、结构版本 | **中文字段名、单位、百分比位数** |
| 渲染器接口、模板与数据分离 | **模板版式**（HTML 样式、后续 PDF/DOCX 模板） |
| 编号与文件名机制 | **编号规则取值**（`MT-<日期>-<4位>`） |
| 归档元数据输出 | **重复生成策略** |
| 用时计算框架 | **用时口径**（起止点定义） |
| 评估装配框架 | **毁伤/效果口径与派生计算式** |

**判据**：引擎公开接口里出现 `搜索覆盖率`、`MT-`、`总体毁伤率` 即破线（这些是规则数据）。

## 6. 风险
