# 待裁决清单（产品口径）

| 项 | 内容 |
|---|---|
| 文档编号 | DECISION-001 |
| 版本 | v0.2 |
| 用途 | 汇总**各波次实现过程中提出的、需要人拍板的产品口径**。全部**不阻塞实现**（引擎已参数化或已给演示值），但定了之后才能出正式交付 |
| 来源 | 各引擎仓 `docs/实现报告.md` 与 `docs/契约/` 的"开放问题"节；`protocol.md` §11；`冲突裁决.md` §10 |

> **裁决日志在别处（v0.2 起）**：本清单只记**尚未裁决**的口径。已拍板的按类分散在三处，别再往回加：
> - **宿主/装配与流程类** → `业务层宿主层实施方案.md` §10（A1–A12：端口、DrogonTransport 归属、
>   仿真悬停、`view-composer` 兄弟段登记、图层组以源码为准…）与 **§10.1**（M5/M6 十问 Q1–Q10）
> - **契约类**（事件名、规则包 schema、兄弟段） → `phase-engine/docs/契约/protocol.md` §4/§5
> - **模块缺陷类** → 各模块的变更请求单：`map-2d变更请求单.md`、`mapApp变更请求单.md`、`geo-data变更请求单.md`
>
> 另：**模块验收必须串行空载跑**（`resource-alloc` 的性能断言对负载敏感），否则会出现"假失败"。

---

## 0. 怎么读

| 标记 | 含义 |
|---|---|
| 🔴 | 影响**跨模块一致性**，越早定越好 |
| 🟡 | 影响**单模块数值口径**，可先用演示值 |
| 🟢 | 影响**界面/交付形态**，可最后定 |

所有条目的共同点：**引擎已就绪，改口径只需改规则包 `policies/`，不需要改代码**（这正是"引擎 vs 规则"分离的收益）。
