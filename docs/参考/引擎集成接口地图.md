> **目标**：不读源码就能写出「11 步业务流程 → 调哪个引擎的哪个方法」的宿主代码。
>
> **口径（硬要求）**
> 1. 本文每一条签名 / 字段都来自**实际读到的行**，形如 `相对路径:行号`（相对 `D:\dsh_workpath\webMap`）。
> 2. 读不到的写「未找到」，**不猜**。
> 3. 行号以本仓当前工作区为准；行号会漂，**符号名不会**——改代码后按符号名重查。

## D.4 与 11 步并行必须补的宿主能力（按依赖排序）

1. **实体/目标/平台 → entity-ledger 的播种**：`registerEntity(RegisterInput)` 需要 `missionId/typeKey/lng/lat/...`；数据源是 `ma::scenario::ScenarioData`（`aircraft[]` / `targets[]` / `zones[]`，见 `packages/scenario-data/include/ma/scenario/scenario_dataset.h:170-218`）。**这本适配器当前不存在**。
2. **`device-ingest` 事件 → `resource-alloc.applyTelemetry` 的汇入腿**：`IngestToHubSink` 现在只把事件广播出去（`ma/hub_engine.cc:22-28`），**没有喂给 resource-alloc / entity-ledger / topology**。需要在这条链上再挂第二个 `device_ingest::ISink`，或在 sink 内部分发（注意 `mergeWindowMs>0` 时只来 `onBatch`）。
3. **`telemetry-store` 写入腿**：目前全工程**没有任何 `store->append(...)` 调用**（§B 2.15）→ 回放/总结无数据。建议在 `IngestToHubSink` 内顺带 `store.append(Record{deviceId, type, ts, data})`（用 `Record::fromEnvelope`，头 `store.h:133`）。
4. **`report-engine` 的 `ITemplateSource`**：为拿到 `reportTemplate.html`，需实现 `ITemplateSource::load(name, out)`（示例拼 `dir + "/" + name + ".html"`），指向 `report-engine/policies/mapapp/`。
5. **`selfcheck` 探针**：至少 5 个分项（对应启动/自检两屏），实现 `ProbeDef.fn`；**必须线程安全且纯**。
6. **命令面骨架**：`POST /api/<verb>` 的统一出入口 + 错误码透传（`code` 原样返回，HTTP 200），见 §A.4 第 8 条。
7. **`/health` 升级**：现在是静态 `{"status":"ok"}`（`host_server.cc:205-211`）；应改为聚合 `selfcheck::healthPayload()` + `gateway->gatewayHealth()` + `tileService->health()` + `store->status()`。
