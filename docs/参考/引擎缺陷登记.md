# 引擎缺陷登记（宿主集成期发现，未改模块源码）

| 项 | 内容 |
|---|---|
| 文档编号 | CR-ENG-001 |
| 版本 | v0.1 |
| 用途 | 宿主装配/集成过程中发现的**模块侧缺陷与"只声明未定义"的坑**。全部**已在宿主侧绕过或适配**，不影响演示；登记在此供各模块按自身需求流程处理 |
| 纪律 | 宿主 MUST NOT 改模块源码绕过；发现即登记 + 在回执/`notes` 里如实点名 |

## CR-ENG-01 · `report-engine`：`toJson()` **只有声明没有定义**（同类：`loadPoliciesFile` 恒失败占位）

`ReportDocument` / `ArchiveMeta` / `GenerateResult` 的成员 `toJson()` 在公开头里有声明，
但 `src/` 里只定义了**同名自由函数**，链接期报 `LNK2019`。
另外 `ReportEngine::loadPoliciesFile` 本身是**故意恒失败的占位**（其源码注释写明）。

**影响**：宿主一旦按"成员函数"写就链不过；按"自由函数"写才可以。
**宿主现状**：用自由函数 `report_engine::toJson(...)`；规则包改为"宿主读 JSON → `loadPolicies(json)`"。
**建议**：要么补齐成员定义，要么在公开头里显式标注"请用自由函数 / 本入口未实现"，避免二次踩坑。

## CR-ENG-02 · `entity-ledger`：`registerEntity` 会把**任务状态写回规则默认态**

当观测（`RegisterInput`）不带动态状态时，归并路径会把已登记的实体状态写回规则包默认态
（`dynamicStates.default = briefStop`）。演示里表现为：目标被打击变灰（`destroyed`）后，
后续探测登记又把它"变回" `briefStop`。

**宿主现状**：探测登记时把**台账现值原样带回**（不让引擎用默认态覆盖），并已写成自证断言。
**建议**：归并时"入参未带状态 → 保留台账现值"，或在契约里写明"调用方必须回填现值"。

## CR-ENG-03 · `entityTypes.json` 的 `dynamicStates` 缺"被打击/被摧毁"状态（**上游已补**）

P6 需要把目标推进到"已打击/已摧毁"，而规则包原先只有 onMove/active/deploying/relocating/briefStop/static。

**处置（上游裁决 A14/A15 口径：规则包是词汇表权威）**：已由上游在
`entity-ledger/policies/mapapp/entityTypes.json` 增补 `struck`（已打击待评估）与 `destroyed`（已摧毁终态）
两个状态 + 5 条迁移（`static/briefStop/active/onMove → struck`、`struck → destroyed`）。
模块验收复跑 **47/47 全绿**。此条属"数据侧补词汇"，不需要改代码 —— 记在这里是为了说明
**"界面要的状态必须先在规则包里存在"**。

## CR-ENG-04 · 键引用不一致：`reportFields.json` 声明的阶段 key 在 `phases.json` 里不存在

报告模板里按阶段 key 取"组网时长"（`mesh-setup`），但 `phase-engine` 的 `phases.json` 里没有这个 key
→ 该字段恒为空。宿主如实置空并在 `dataGaps` 里点名（**不编时长**）。
**建议**：两包键引用做一次交叉校验（或把该字段的 key 取自 `phases.json` 的真实阶段）。

---

## CR-ENG-05 · `SimSource::init` 会把仿真时钟归零

`init()` 之后 `simEpoch0Ms`/`simElapsedMs` 从 0 起算，因此"俯冲段时刻"是**仿真相对毫秒**，
不是挂钟。宿主在回执里给出 `simEpoch0Ms` 并注明口径。
**建议**：在公开头注释里写明"init 归零"，避免调用方把它当挂钟用。
