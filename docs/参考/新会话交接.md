## 5. 纪律与坑（**这一节最省时间，务必读**）

### 5.1 不可协商的三条纪律

1. **模块源码一行不拷、一行不改**：`add_subdirectory(<模块目录> <build子目录>)` 原地引用，宿主只 include 公开头。
   确需改模块 → 在**它自己的仓**里改，并附需求与验收。
2. **宿主里没有业务逻辑**：业务取值全在规则包；连 11 步的**显示名**也在 `config.json` 的 `flow.steps`、
   界面文案与**语音台词**在 `flow.labels`。验收的 **S1/S1b** 两条守卫盯着这件事（S1=标识符层无业务词，S1b=业务词只许出现在诊断文案里）。
3. **数据不许编**：屏上每个数字都要能在 verb 回执里找到来源；拿不到 → 显示"—"/"未提供" + **写明原因**，
   MUST NOT 显示 0、MUST NOT 抄参考图上的示意值。

### 5.2 工程坑（都踩过，别再踩）

| 坑 | 症状 | 正解 |
|---|---|---|
| **前端产物不入库** | 页面空白 | 改完前端必须 `cd apps\web; npm run build` |
| **`inset` 简写** | 切屏后整屏塌成 0 高、内容跑到视口外 | React style 一律用 `left/right/top/bottom` 长写 |
| **只用 `flow.goto` 推流程** | 屏幕到了第 6 步、阶段还停在 T0，后续 verb 全被门禁拒 | 用 `App.tsx` 的 `goto()`（先 `mission.advance` 阶段链，再 `flow.goto` 落屏） |
| **`.ps1` 没有 BOM** | Windows PowerShell 5.1 按 ANSI 读 → 中文乱码 + 语法错 | 带中文的 `.ps1` 一律 **UTF-8 with BOM**（`scripts\*.ps1` 都是；`acceptance.ps1` 有硬校验） |
| **`Start-Process -RedirectStandardOutput`** | PS 5.1 上脚本卡住不返回（它等子进程退出） | 用宿主自带的 `--log <文件>`（`demo.ps1` 就是这么写的） |
| **两条宿主实例同端口** | 后起的那条 `packets=0`、启动加载卡 50% | 必须同时错开 **UDP 接入端口**：`demo.ps1 serve -Port 8100 -IngestPort 45501` |
| **并发跑验收** | 互相打断、流程被推走 | 验收脚本**串行**跑；它们都驱动同一个宿主 |
| **hub 判死 4.5 s** | 页面切屏慢半拍、`/stats` 的 `clientCount` 恒 0 | 客户端心跳必须更密（页面已用 `heartbeatMs: 1200`）；改判死窗要一起改 |
| **headless 连续截图** | 同一个 page target 连截十几屏 → `Page.captureScreenshot` 超时 | **一屏一个全新 page target**（`scripts\screenshots.mjs` 已按这个写），失败重试一次 |
| **`Select-Object -First N` 接长跑进程** | 管道被截断、进程被杀 | 用后台任务（`run_in_background`）或重定向到文件 |
| **GitHub 推送偶发 SSL 失败** | `SSL_ERROR_SYSCALL`（代理开关是用户管理的，别去动它） | **重试一次**通常就好；失败就稍后再推，别改代理配置 |

### 5.3 关于"用代理/子代理干活"（上一轮教训）

上一轮之所以要换新会话，是因为**并行代理太多**。经验：

- **同一个文件只能有一个写者**：按**文件**切分任务，别按"阶段"切（否则两人改 `App.tsx`/`registry.ts` 必冲突）。
- 结构件（屏路由、全局框架、`App.tsx`）**由主会话自己写**，只把**互不相交的屏文件**派给子代理。
- 每个子代理的提示里必须写死：**导出契约（props 签名）**、**只改哪几个文件**、**不许动 `App.tsx`/`registry.ts`/`shell/`**、
  **自证方式**（`cd apps\web; node node_modules\typescript\bin\tsc --noEmit` 必须 0 错误；**不要**跑 `vite build`，
  避免多个代理抢 `dist/`）。
- 集成时统一跑一次 `tsc` + `vite build` + `click-check` + `p2–p7`，任何一条红都先查是不是"两个写者"造成的。
