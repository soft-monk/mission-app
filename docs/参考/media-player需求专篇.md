## 1. 定位与边界

### 1.1 定位

media-player 是**媒体呈现层**，不认识地图、不认识任务、不认识网络：

```
媒体素材（本地 mp4 / 图像流 / 可选远程流）
   │ 由宿主后端托管：/media/**（Range）
   ▼
┌──────────────────────────────────────────────────────────┐
│  media-player                                            │
│  通道与源 CHN → 播放控制 PLY → 多路同屏 MUL                 │
│                      │                                   │
│                      ├──► 叠加层 OVL（锁定框/倍率/时间戳）   │
│                      └──► 降级与状态 DGR（就绪/错误/隐藏）   │
└──────────────────────┬───────────────────────────────────┘
                       │ props 进 / 回调出
                       ▼
        宿主（布局与业务绑定）—— 地图侧另有 map-2d
```

**一句话**：media-player 回答"**给我一路或几路画面，我怎么稳定地放出来、叠上必要的标记、并在没有画面时不添乱**"。
它不回答"这路画面属于哪个集群、该和地图怎么联动"——那是宿主与 `situation-layer` 的事。

### 1.2 为什么必须是独立模块

| 依据 | 原文 | 含义 |
|---|---|---|
| 初稿 §6 T3-2 / §8 T3-2 / T6-1 / T6-2 | 六路集群图像流、三路实时图像流、多源融合三路（光电/雷达/电子）、实时回传画面三路 | **画面是至少四处界面的主体内容**，不是边角装饰 |
| 概要设计 §3.4 / §8.3 | 「media/：视频面板组件（`<video>` 封装）+ 多路图像流卡（缩放↔全屏）」；「无视频素材：视频入口自动隐藏，不显示空面板」 | 已有形态，但**与业务面板同层**，无法独立自证 |
| `map-2d` M2-MZ-04 / M2-NFR-04 | 「整目录拷贝到新项目即可编译运行」 | 并列模块按同一套解耦基准要求，媒体模块没有理由例外 |

**多路同屏 + 节流 + 资源上限**是有真实性能风险的部分；放在业务壳里意味着它**永远无法被独立压测**。

### 1.3 范围边界

| 边界 | 内容 |
|---|---|
| 🚫 不做地图 | 不接触 MapLibre / 图元；**MUST NOT import `map-2d`**，也 MUST NOT import `ws-client`（与地图模块同一条红线） |
| 🚫 不做业务 | 不含任务、阶段、目标、集群、威胁等级、毁伤状态等语义；画面叠加内容一律由宿主以数据注入 |
| 🚫 不做协议接入 | RTSP/GB28181/RTP 等**远程流接入不在本期**（TR-VID-04 当前无需求，仅留扩展点） |
| 🚫 不做转码与推流 | 服务端不转码；浏览器原生解码本地 mp4（概要设计 D6） |
| 🚫 不做视频存储与留存 | 媒体文件由宿主静态托管；录制/归档不在本期 |
| 🚫 不做图像识别 | 锁定框、目标框来自业务侧数据，本模块只负责**画在正确的位置** |
| 🚫 不做通道清单的权威存储 | 清单来源由宿主决定（接口/配置/内置示例），本模块只消费 |

### 1.4 硬约束（来自既有契约，不得破坏）

| 约束 | 取值 | 依据 |
|---|---|---|
| 静态资源 | `/media/**`（视频），静态托管 MUST 支持 **Range**（拖动进度依赖它） | 契约 §1 |
| 通道清单接口 | `GET /api/v1/media/videos` → `[{ name, url }]` | 契约 §3.9 |
| 地图配置中的视频字段 | `GET /api/v1/map/config` 的 `video?: []`（保留字段） | 契约 §3.1 |
| 无素材降级 | 无视频素材时**入口自动隐藏，不显示空面板** | 契约 §8 降级表 |
| 部署形态 | 浏览器多终端、平板横屏优先、**客户端零安装**；媒体本地托管 | 契约 §1；概要设计 §2 D6 |
| 默认隐藏 | 本模块自身**不产生**外网请求；素材全本地 | NFR-02 |
| 安全上下文 | 若涉及麦克风采集，内网 HTTP 下 Chromium 拒绝 `getUserMedia`（需 HTTPS） | TRD §4.6 技术前置 ⏸ |

## 3. 功能需求条目

### 3.1 通道与源（MDP-CHN）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| MDP-CHN-01 | **MUST** 通道模型：一个通道含 `{ id, 名称, 类型, url/素材, 来源标识?, 可用性 }`；`类型` 至少覆盖 `video`（mp4）与 `image-seq`（图像流） | 两类通道均可被列举与播放；字段缺省有定义行为、不报错 | ⏳ |
| MDP-CHN-02 | **MUST** 通道清单注入：清单来源由宿主提供（接口 / 配置 / 内置示例），本模块 MUST NOT 硬编码任何通道名与 URL | 换成宿主的清单即换通道；模块源码内检索不到任何具体通道名 | ⏳ |
| MDP-CHN-03 | **MUST** 与既有接口兼容：能直接消费 `GET /api/v1/media/videos` 的 `[{name, url}]`（字段缺失时按默认类型处理） | 用既有接口原样返回的数据即可播放，无需宿主改接口 | ⏳ |
| MDP-CHN-04 | **MUST** 运行时切换通道：切换后旧通道 MUST 被正确释放（停止解码、释放缓冲），不残留后台播放 | 连续切换 20 次后，内存与解码实例无持续增长；旧通道无声音残留 | ⏳ |
| MDP-CHN-05 | **SHOULD** 来源标识：通道可携带来源标识（如 光电/雷达/电子/通用），用于**显示**来源徽标；模块 MUST NOT 内置任何来源枚举 | 不传来源时不显示徽标且不报错；传入任意字符串均可正确显示 | ⏳ |

### 3.2 播放控制（MDP-PLY）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| MDP-PLY-01 | **MUST** 基础控制：播放 / 暂停 / 停止 | 三个动作均可由接口与界面触发，状态可查询 | ⏳ |
| MDP-PLY-02 | **MUST** 进度控制：进度条显示与拖拽定位；依赖服务端 **Range** 支持 | 拖到任意位置立即从该处继续；无 Range 时给出可读降级提示而非静默失败 | ⏳ |
| MDP-PLY-03 | **MUST** 音量与静音：音量调节、一键静音；**多路同屏时默认至多一路出声**（避免叠音） | 六路同屏时只有一个通道出声；切换主路时声音跟随 | ⏳ |
| MDP-PLY-04 | **SHOULD** 倍速与单帧步进：倍速（至少 0.5×/1×/2×）；`video` 通道支持单帧步进 | 倍速切换生效；单帧步进逐帧推进可复现 | ⏳ |
| MDP-PLY-05 | **MUST** 全屏：单通道可放大到全屏；退出后回到原布局且播放位置不丢 | 全屏 ↔ 退出后播放进度连续，布局恢复一致 | ⏳ |
| MDP-PLY-06 | **MUST** 循环与首帧策略：可配置循环播放；图像流 MUST 支持按固定间隔自动轮播（作为"实时"感的实现方式） | 循环开启后无间断；图像流按配置间隔切换且可暂停 | ⏳ |

### 3.3 多路同屏（MDP-MUL）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| MDP-MUL-01 | **MUST** 多路同屏：至少支持 **6 路**同屏（初稿六路图像流、三路回传画面） | 六路同时播放不崩、不互相顶掉 | ⏳ |
| MDP-MUL-02 | **MUST** 每种通道类型的最多路数可配，并有明确上限保护 | 超过上限时拒绝新增并给出可读原因（不静默丢） | ⏳ |
| MDP-MUL-03 | **MUST** 按需加载与有界缓存：非可见路 MUST 可暂停或降频；缓冲 MUST 有上限 | 隐藏多路后解码与下载活动显著下降；长时间运行内存不持续增长 | ⏳ |
| MDP-MUL-04 | **SHOULD** 布局与主路：支持网格布局与"指定一路为主路"（放大、出声）；主路可被宿主设置 | 指定主路后布局与声音跟随；取消主路后回到网格 | ⏳ |
| MDP-MUL-05 | **SHOULD** 节流：高频图像流可配置最小刷新间隔（合并窗口），避免整屏重排 | 把间隔设为 100 ms 后，更新次数下降而观感连续 | ⏳ |

### 3.4 叠加层（MDP-OVL）

> 初稿里这些标注是**逐屏明确的**，不是装饰：
> 倍率与【实时】标识（场景三 T2-2）、红色锁定十字框（§8 T6-2）、时间戳与"实时"（§6 T3-2 多源标识）。

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| MDP-OVL-01 | **MUST** 可开关的叠加项：至少覆盖 `实时/回放标识`、`倍率`、`时间戳`、`通道名`、`来源徽标` | 逐项开关生效；关闭后不残留占位 | ⏳ |
| MDP-OVL-02 | **MUST** 叠加内容由宿主注入，模块不产生业务语义 | 不注入时各项不显示且不报错；注入任意文本均正确渲染 | ⏳ |
| MDP-OVL-03 | **MUST** 锁定框/框选：支持在画面内绘制矩形锁定框（含十字准星样式），位置以**归一化坐标（0–1）**表达 | 不同分辨率下框位置比例一致；窗口 resize 后位置正确跟随 | ⏳ |
| MDP-OVL-04 | **MUST** 叠加层与画面帧对齐：缩放、全屏、窗口变化时叠加层 MUST 与画面同步，不出现错位 | 连续 resize 与全屏切换过程中无可见错位 | ⏳ |
| MDP-OVL-05 | **SHOULD** 叠加层不干扰控制：叠加元素 MUST NOT 吞掉播放控件的点击；可配置为"穿透" | 开启穿透后点击落到底层控件；关闭后叠加元素可命中 | ⏳ |

### 3.5 降级与状态（MDP-DGR）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| MDP-DGR-01 | **MUST** 状态可观测：对外暴露每条通道的状态（`idle`/`loading`/`ready`/`playing`/`paused`/`error`）与错误原因 | 宿主可实时查询；状态迁移可复现 | ⏳ |
| MDP-DGR-02 | **MUST** 无素材降级：清单为空或无可用通道时，MUST **隐藏入口/空面板**并给出可读原因，MUST NOT 显示空白黑框 | 清单为空时界面无空面板；原因可读（契约 §8） | ⏳ |
| MDP-DGR-03 | **MUST** 单路失败不影响其它路：某路 404/解码失败时，其余路 MUST 继续正常播放 | 故意让一路 url 无效，其余五路不受影响；失败路显示可读错误态 | ⏳ |
| MDP-DGR-04 | **SHOULD** 诊断信息：可读的连接/加载耗时、实际分辨率、缓冲次数、丢帧次数 | 面板或接口可取到；用于排障而非业务展示 | ⏳ |

### 3.6 非功能性（MDP-NFR）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| MDP-NFR-01 | **MUST** 性能：6 路同屏时界面帧率不低于 **25 fps**；`video` 通道首帧 ≤ 1 s、拖动定位 ≤ 500 ms（局域网） | 实测达标并可复现 | ⏳ |
| MDP-NFR-02 | **MUST** 零业务耦合：全仓检索不出现 `任务/方案/目标/场景/阶段/编组/评估` 等业务词；MUST NOT import `map-2d` 或 `ws-client` 的内部 | 全仓检索零命中；`grep` 跨仓 import 零命中 | ⏳ |
| MDP-NFR-03 | **MUST** 独立交付：独立构建、独立示例（自带示例素材或本地占位）、独立测试、独立验收脚本（退出码 0/1），不依赖宿主与后端 | 空环境 clone → 一条命令构建 → 一条命令验收通过 | ⏳ |

## 4. 与 `map-2d` 的关系（必须写清，否则必然打架）

两个模块在界面上经常同屏出现，边界必须一句话说清：

| 事项 | media-player | map-2d |
|---|---|---|
| 画**视频/图像** | ✅ | 🚫 |
| 画**地图与图元** | 🚫 | ✅ |
| 锁定框画在哪 | **在画面内**（归一化坐标） | **在地图上**（经纬度） |
| 谁把"目标在地图上的位置"换算成"画面里的像素位置" | 🚫 **两家都不做** | 🚫 |
| 上述换算的归属 | **宿主 / `situation-layer`**（需要相机内外参与视场参数，属业务装配） | — |

**红线**：两个模块 MUST NOT 互相 import；同屏布局由宿主负责。
`realtime-hub` README 的原话同样适用于此：适配器同时 import 两个包是**对的**，模块内部互相 import 是**破线**。

## 5. 决策记录

| 编号 | 议题 | 决策 | 影响 |
|---|---|---|---|
| MD1 | 视频源形态 | **本地 mp4 + 浏览器原生解码**，不做转码、不做流媒体服务 | MDP-CHN-01；远程流仅留扩展点 |
| MD2 | "实时图像流"怎么实现 | **序列帧（jpg/png）轮播** 作为本期实现（本地 mp4 无法表达"实时"）；远程流后期接入 | MDP-CHN-01、MDP-PLY-06 |
| MD3 | 多路同屏的出声策略 | **默认至多一路出声**，主路跟随 | MDP-PLY-03、MDP-MUL-04 |
| MD4 | 叠加层技术形态 | 用 **DOM/CSS 或 SVG** 覆盖在媒体元素之上，归一化坐标；MUST NOT 侵入媒体解码链路 | MDP-OVL-03/04 |
| MD5 | 与地图的联动换算（视场/像素） | **不在本模块**，也不在 `map-2d`；由宿主 / `situation-layer` 承担 | §4 |
| MD6 | 远程流是否本期做 | **不做**（TR-VID-04 无需求）；但通道模型预留 `类型` 字段以便后期扩展 | MDP-CHN-01 |
| MD7 | 通道清单的权威来源 | 初期用 `GET /api/v1/media/videos`；本模块只消费清单，**清单存储不属本模块** | MDP-CHN-02/03 |

## 6. 风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 六路同屏在国产化平板上可能达不到 25 fps | 体验不达标 | MDP-MUL-03/05 按需加载 + 节流设为 MUST/SHOULD；MDP-NFR-01 作为观测门槛，必要时降为 4 路 |
| R2 | 无真实素材时演示"空面板" | 现场尴尬 | MDP-DGR-02 隐藏入口；提供**内置示例素材**（通用虚构内容，不含业务信息）随模块交付 |
| R3 | 序列帧方案在低配设备上抖动 | 观感差 | MDP-MUL-05 最小刷新间隔 + 预加载下一帧 |
| R4 | 叠加层与画面错位（尤其全屏切换时） | 视觉错误、被误判为"标错了" | MDP-OVL-04 设为 MUST 并纳入验收；用归一化坐标而非像素坐标 |
| R5 | 麦克风/语音相关能力被误塞进本模块 | 边界破线 | 本模块只管**画面**；语音属 `voice-interaction`（TR-VOI），且受 HTTPS 前置约束 |
| R6 | 通道清单里的 URL 变成硬编码 | 不可交付 | MDP-CHN-02 验收：全仓检索不到任何具体通道名与 URL |

## 7. 验收清单（模块专项）

- [ ] 空环境 clone → 一条命令构建 → 一条命令跑通验收脚本（退出码 0）
- [ ] 独立宿主内可播放 `video` 与 `image-seq` 两类通道，不接主系统与后端
- [ ] 用 `[{name,url}]` 原样数据即可播放（与既有 `/api/v1/media/videos` 兼容）
- [ ] 换一份宿主清单即换通道；模块源码检索不到任何具体通道名与 URL
- [ ] 连续切换通道 20 次，无内存增长、无声音残留
- [ ] 进度拖拽依赖 Range 生效；无 Range 时给出可读降级提示
- [ ] 六路同屏：只有一路出声；切换主路声音跟随
- [ ] 全屏 ↔ 退出后播放进度连续、布局一致
- [ ] 序列帧通道按配置间隔轮播，可暂停
- [ ] 隐藏多路后解码/下载活动显著下降；长时间运行内存有界
- [ ] 叠加项逐项开关生效；锁定框在不同分辨率下比例一致，resize/全屏后不错位
- [ ] 清单为空时无空面板且原因可读
- [ ] 故意让一路 url 无效，其余路不受影响
- [ ] 6 路同屏帧率 ≥ 25 fps；首帧 ≤ 1 s；拖动定位 ≤ 500 ms（局域网）
- [ ] 全仓检索业务词零命中；`map-2d` / `ws-client` 跨仓 import 零命中
- [ ] 断外网时全部功能可用（素材本地）
