## 1. 定位与边界

### 1.1 定位

geo-data 是**数据供给层**，不是地图的一部分，也不是业务的一部分：

```
上游数据源（栅格影像 / 矢量样式 / 授权数据）
   │ 取源（一次性、可离线、受政策约束）
   ▼
┌──────────────────────────────────────────────────────────┐
│  geo-data                                                │
│  源与合规 SRC → 切图打包 PKG → 清单校验 MNF                │
│                      │                                   │
│                      ▼                                   │
│          服务端托管 SRV（HTTP + Range + 缓存语义）          │
│                      │                                   │
│          运行时契约 RTM（模板/多包注册/缺块感知）            │
└──────────────────────┬───────────────────────────────────┘
                       │ tileUrlTemplate + 清单 + 健康态
                       ▼
       宿主（配置装配）──► map-2d（渲染，不认识瓦片从哪来）
```

**一句话分工**：geo-data 负责"**把地理数据变成局域网里拿得到、校验得过、切得动的一套瓦片包**"；
`map-2d` 负责"**按宿主给的模板把瓦片画出来**"；两者之间只有 **URL 模板 + 可读清单** 这一层契约。

### 1.2 为什么必须是独立模块

不是"顺手加个脚本"，而是三条既有边界共同把它挤了出来：

| 依据 | 原文 | 含义 |
|---|---|---|
| `map-2d` §0.3 | 「🚫 瓦片工程：切图、抓取、打包、分发」「🚫 在线底图适配：不内置任何在线底图源……底图数据一律本地化，地址由宿主配置」 | **消费侧明确不承接生产侧** |
| `map-2d` M2-BASE-08 | 「瓦片包版本与完整性校验：可查询瓦片包版本与缺块清单」 | 消费侧**已经预留了"包"这个概念**，生产侧却是空的 |
| `TR-GEO-04` | 「数据合规：开发验证期遵守 OSM Tile Usage Policy；生产自渲染或合规数据源」 | 合规责任需要一个**有归属的执行点**，不能散在脚本里 |

### 1.3 范围边界

| 边界 | 内容 |
|---|---|
| 🚫 不做渲染 | 不接触 MapLibre / WebGL / 图元；"画成什么样、缺口怎么兜底"属 `map-2d` |
| 🚫 不做地图控件与业务 | 不含比例尺/指北针/量算/图层开关/显示模式，不含任务、区域、目标等业务语义 |
| 🚫 不做在线底图的运行时适配 | 不内置任何在线源、不做坐标系偏移（GCJ-02 等）适配；离线优先（GEO-SRC-03） |
| 🚫 不做网格换算的重复实现 | MGRS / UTM / 经纬网换算 `map-2d` 已实现（M2-MAP-08）；本模块 MAY 只做切片期校验用，**不得**成为第二份实现 |
| 🚫 不做三维数据管线 | DEM 地形、3D Tiles、倾斜摄影、BIM **全部已放弃**（初稿附录 A/B、TRD v1.2）；瓦片目录**不含** `dem/`、`3dtiles/` |
| 🚫 不做权限与鉴权 | 静态资源对内网开放；鉴权/TLS 属独立课题 |
| 🚫 不做 CDN / 集群分发 | 局域网单机托管为本期形态；PMTiles 为可选升级（GEO-PKG-06） |
| 🚫 不承担数据版权责任 | 模块提供合规**机制**（来源登记、限速、署名、许可记录）；**具体来源的授权由使用方负责** |

### 1.4 硬约束（来自既有契约，不得破坏）

| 约束 | 取值 | 依据 |
|---|---|---|
| 静态资源路径 | `/tiles/**`（瓦片）、`/media/**`（媒体）、`/reports/**`（报告）、`/`（前端） | 契约 §1 |
| Range 请求 | 静态托管 MUST 支持 | 契约 §1 |
| 底图配置接口 | `GET /api/v1/map/config` → `basemap: { tileUrlTemplate, attribution }`（**无 terrain / 3dtiles 字段**） | 契约 §3.1 |
| 后端端口 | `8080`（可配）；监听内网网卡 | 契约 §1 |
| 坐标系 | 数据 WGS84；瓦片 Web Mercator；MapLibre 自动投影 | TRD D2 |
| 无外网前提 | 断外网时地图 MUST 仍可用（重资源本地化） | NFR-02 |
| 瓦片精度上限 | 模块按地面分辨率限制最细层级 | `map-2d` M2-BASE-05 |
| 版权标注 | 开关由 `map-2d` 的 `MAP_OPTIONS.showAttribution` 控制（当前**默认隐藏**） | GEO-05 / 地图专篇 §7 |

## 3. 功能需求条目

### 3.1 源与合规（GEO-SRC）

> 本域**只做机制与登记**，不做数据版权判断。

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| GEO-SRC-01 | **MUST** 源登记：每个数据源登记 `{ id, 名称, 类型(raster\|style), 许可/署名, 层级范围, 坐标系, 取源方式 }`，登记信息可查询、可导出 | 枚举源清单时每项字段完整；未登记来源无法进入打包流程（明确报错） | ⏳ |
| GEO-SRC-02 | **MUST** 政策合规机制：批量取源 MUST 支持速率上限、并发上限、`User-Agent` 标识、失败退避；违规参数（并发过高）MUST 被拒绝并给出可读原因 | 故意把并发调到超限值，工具拒绝执行并说明；按合规参数执行时无 429/封禁 | ⏳ |
| GEO-SRC-03 | **MUST** 离线优先：**默认运行时服务 MUST 不依赖任何外网请求**；取源是**一次性离线工序**，与运行时完全分离。若某包确需外部托管（如宿主配置的在线 style URL），MUST 在该包的源登记中显式标记为 `external`，否则视为违反 | 拔掉外网后，`external` 标记为假的包全部正常出图；抓包确认这些包零外部请求；存在 `external` 包时可查询到该标记 | ⏳ |
| GEO-SRC-04 | **MUST** 坐标系一致性：输入数据一律视为 **WGS84**，瓦片一律 **Web Mercator**；MUST NOT 内置 GCJ-02/BD-09 偏移转换 | 同一经纬度在瓦片与矢量图上落点一致，无系统性偏移 | ⏳ |
| GEO-SRC-05 | **SHOULD** 多区域组合：支持按"场景/战区名称 → 数组包"映射，多城市/多战区靠**目录合并**而非重新切图 | 增加第二个区域只需追加一个包目录，主程序与前端零改动 | ⏳ |

### 3.2 切图与打包（GEO-PKG）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| GEO-PKG-01 | **MUST** 预切栅格瓦片：按标准 **XYZ 目录** `{z}/{x}/{y}.{ext}` 产出，`ext` 支持 `jpg`/`png`/`webp` | 产物可直接被 `map-2d` M2-BASE-01 消费（模板 `{z}/{x}/{y}`），无需转换 | ⏳ |
| GEO-PKG-02 | **MUST** 范围与层级可配：区域 bbox、`minZoom`/`maxZoom`、输出格式与质量全部可配，不硬编码 | 改配置重新打包即改变覆盖范围与层级，无代码改动 | ⏳ |
| GEO-PKG-03 | **MUST** 面积—数据量控制：最高层级 MAY 超出演示范围，但 MUST 提供"超出即拒绝+提示"的保护（防数据量爆炸） | 故意配一个异常组合（如全国 z18），工具拒绝并给出估算量；正常配置可完成 | ⏳ |
| GEO-PKG-04 | **MUST** 断点续传与幂等重跑：中断后重跑 MUST 跳过已完成瓦片；产出结果 MUST 可复现（同配置同输入 → 同清单） | 中途 kill 再重跑，已完成瓦片不重复抓取；两次完整运行清单键列表一致 | ⏳ |
| GEO-PKG-05 | **MUST** 跨平台：Windows 与 Linux 均可执行；MUST NOT 依赖宿主项目目录结构 | 在空目录（仅本模块）下用最小配置跑通一次小范围打包 | ⏳ |
| GEO-PKG-06 | **MAY** PMTiles 单文件输出：作为瓦片分发升级选项，产物需可被消费侧以单文件方式读取 | 按需实施（当前 = 不实施） | ⏳ 按需 |

### 3.3 清单与校验（GEO-MNF）

> 本域是**包格式的定义方**，也是 `map-2d` M2-BASE-08「可查询瓦片包版本与缺块清单」的服务端一半。

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| GEO-MNF-01 | **MUST** 包清单文件：随包产出 `manifest.json`，至少含 `{ version, 生成时间, 源登记 id, 层级范围, 各层瓦片数, 键列表或键范围, sha256 摘要 }` | 清单可被机器读取并逐字段校验；缺字段即视为无效包 | ⏳ |
| GEO-MNF-02 | **MUST** 清单与瓦片目录一致：清单 MUST 从**实际瓦片目录**生成（不依赖打包过程的中间状态） | 人工删掉 3 张瓦片后重新生成清单，清单内数量与键列表同步减少 | ⏳ |
| GEO-MNF-03 | **MUST** 完整性校验：支持**清单比对 + 抽样探测**两档；两档结果 MUST 给出可读结论 | ① 完整包：校验通过；② 随机删块：比对档列出缺块；③ 清单缺失时降级为**抽样探测**并给出可读原因（不得静默通过） | ⏳ |
| GEO-MNF-04 | **MUST** 缺块清单输出：可导出缺失的 `z/x/y` 键列表（供补块与消费侧展示） | 导出的清单逐条对应真实缺失文件，无多报无漏报 | ⏳ |
| GEO-MNF-05 | **SHOULD** 版本与摘要稳定：`version` 由打包配置显式给定（不是自动递增），摘要 MUST 覆盖清单全部键 | 同配置重跑得到同 `version` 与同摘要；改动一块瓦片摘要必变 | ⏳ |

### 3.4 服务端交付（GEO-SRV）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| GEO-SRV-01 | **MUST** 瓦片服务：以 HTTP 静态托管提供瓦片，路径模板宿主可配（默认 `/tiles/raster/{z}/{x}/{y}.jpg`） | 浏览器直连该模板可取得瓦片；与 `map-2d` 的 `tileUrlTemplate` 对接即出图 | ⏳ |
| GEO-SRV-02 | **MUST** 正确响应头：按扩展名给出正确 `Content-Type`；缓存语义支持 `Cache-Control: immutable` + 长有效期；MUST 支持 `ETag` 或 `Last-Modified` | 浏览器二次访问命中缓存；`Range` 请求返回 206 且区间正确（契约 §1） | ⏳ |
| GEO-SRV-03 | **MUST** 缺失语义明确：不存在的瓦片 MUST 返回 **404 或 204**，MUST NOT 返回 200 + HTML 错误页 | 请求故意不存在的键，响应码与响应体符合约定，前端不会当成有效图片 | ⏳ |
| GEO-SRV-04 | **MUST** 单瓦片响应 ≤ 10 ms（局域网，含磁盘读取与写回），并纳入可观测统计 | 连续请求 1000 次，P95 ≤ 10 ms 并可读取统计 | ⏳ |
| GEO-SRV-05 | **MUST** 请求洪峰不影响其它端点：瓦片请求 MUST NOT 阻塞 `/api/v1/*` 与 `/ws` | 一边并发拉瓦片一边调 `/api/v1/health`，后者延迟无显著上升 | ⏳ |
| GEO-SRV-06 | **MUST** 多包并列挂载：同一服务端可同时挂载多个瓦片包（不同区域/版本），按配置前缀区分 | 两包同时挂载，两套模板均可取到各自瓦片，互不串台 | ⏳ |

### 3.5 运行时托管契约（GEO-RTM）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| GEO-RTM-01 | **MUST** 模板变量语义公开且冻结：`{z}`/`{x}`/`{y}` 的含义与替换规则 MUST 成文；变更 MUST 走破坏性变更流程 | 文档中模板规范与实现逐条一致；换实现方按文档即可对接 | ⏳ |
| GEO-RTM-02 | **MUST** 版本化路径或指纹：包路径 MUST 含版本（如 `/tiles/<pkg>-<version>/...`），使缓存失效可控 | 换包版本后旧缓存不被复用；同版本重访命中缓存 | ⏳ |
| GEO-RTM-03 | **MUST** 包清单查询接口：提供"可枚举包清单 + 每包元数据（版本/层级/瓦片数/是否就绪）"的服务端能力，供宿主配置与自检**一次取到** | 一次调用返回全部包及其元数据；未就绪的包被如实标注 | ⏳ |
| GEO-RTM-04 | **SHOULD** 健康探针：暴露"瓦片目录是否存在、清单是否可读、抽样瓦片是否可取"三项探测结果，可被 `selfcheck` 聚合成启动界面「地图引擎」一项 | 故意移走瓦片目录，探针返回可读失败原因而非超时 | ⏳ |

### 3.6 非功能性（GEO-NFR）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| GEO-NFR-01 | **MUST** 性能：单个瓦片请求 ≤ 10 ms（局域网）；1000 次并发请求零错误、P95 ≤ 50 ms | 实测达标并可复现 | ⏳ |
| GEO-NFR-02 | **MUST** 内存有界：服务端**不得**把整包读入内存（流式读盘 + 传输）；常驻内存与包大小无关 | 挂载大包（≥ 100 万张）后 RSS 无显著增长 | ⏳ |
| GEO-NFR-03 | **SHOULD** 传输可压缩：可选的传输压缩（至少对文本类 manifest 生效）；压缩不得破坏 Range 语义 | manifest 启用压缩后体积下降；瓦片 Range 仍正确返回 206 | ⏳ |
| GEO-NFR-04 | **MUST** 零业务依赖：全仓检索不出现 `任务/方案/目标/场景/阶段/编组/评估` 等业务词；MUST NOT 依赖主系统的 store、面板、组件库 | 全仓检索零命中（可脚本化）；本模块可在空工程内独立构建运行 | ⏳ |
| GEO-NFR-05 | **MUST** 独立交付：具备独立构建、独立示例、独立测试、独立验收脚本（退出码 0/1），不依赖宿主 | 空环境 clone → 一条命令构建 → 一条命令验收通过 | ⏳ |

## 4. 包目录与分发形态（建议）

```
<tiles-root>/
  <pkg>-<version>/                    ← 一包一版本目录（GEO-RTM-02）
    manifest.json                     ← 包清单（GEO-MNF-01）
    raster/
      {z}/{x}/{y}.jpg                 ← XYZ 栅格瓦片（GEO-PKG-01）
```

分发：单包 zip + 安装脚本（安装/卸载/升级/校验四件事），或直接共享盘拷贝。
**目录里不含** `dem/`、`3dtiles/`（三维能力已放弃，初稿附录 A/B）。

## 5. 决策记录

| 编号 | 议题 | 决策 | 影响 |
|---|---|---|---|
| GD1 | 切图与取源是否在运行时做 | **不做**。取源/切图是**一次性离线工序**；运行时只有静态托管 | GEO-SRC-03；本模块同时含"工具"与"服务"两个可独立构建的产物 |
| GD2 | 服务端实现语言 | **随宿主**：接口与路由处理器**框架中立**，由宿主注入挂载；模块自身不依赖 Web 框架 | GEO-SRV-01；对齐 `device-ingest` 的做法（路由由宿主挂载） |

| GD5 | 清单格式用 JSON 还是别的 | **JSON**（可机器读取、可入库、可 diff），摘要用 sha256 | GEO-MNF-01/05 |
| GD6 | 包格式是否支持 PMTiles | **暂不**，作为可选升级（GEO-PKG-06）；当前 XYZ 目录已满足局域网性能 | 无代码影响 |

## 6. 风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | **数据来源合规责任不清**（GEO-SRC-02 只给机制，不给授权） | 法律与分发风险 | 源登记中**强制**填写许可与署名；交付时随包附来源清单；生产环境改用自渲染或合规源（TR-GEO-04） |
| R2 | 大包场景下"整目录校验"耗时过长 | 上线/自检卡顿 | GEO-MNF-03 分两档：清单比对（快）+ 抽样探测（慢，可选）；自检默认用探针（GEO-RTM-04）而非全量校验 |
| R3 | 瓦片请求与 REST 抢同一进程 I/O | 高频瓦片拉取拖慢 API | GEO-SRV-05 设为 MUST 并纳入验收；必要时宿主分端口或加并发上限 |
| R4 | 多包挂载时路径前缀冲突 | 串台 | GEO-SRV-06 验收要求两包并列可分辨；配置层做前缀唯一性校验 |
| R5 | 缓存失效策略配错导致"换了包还是旧图" | 现场返工 | GEO-RTM-02 强制版本化路径；换包即换路径 |

## 7. 验收清单（模块专项）

- [ ] 空环境 clone → 一条命令构建 → 一条命令跑通验收脚本（退出码 0）
- [ ] 按最小配置完成一次小范围打包，产出 XYZ 目录 + `manifest.json`
- [ ] 中断重跑：已完成瓦片不重复抓取，最终清单与一次跑完一致
- [ ] 打包工具在并发超限时拒绝执行并给出可读原因
- [ ] 完整性校验：完整包通过；人工删块后清单比对列出缺块；删掉清单后降级为抽样探测并说明原因
- [ ] 缺块清单导出的键与真实缺失文件逐条一致
- [ ] 服务端挂载后，`map-2d` 只改 `tileUrlTemplate` 即可出图，模块源码零改动
- [ ] 不存在的瓦片返回 404/204，不返回 200 + HTML
- [ ] `Range` 请求返回 206 且区间正确；二次访问命中缓存
- [ ] 1000 次并发瓦片请求零错误、P95 ≤ 50 ms；单瓦片 P95 ≤ 10 ms
- [ ] 并发拉瓦片时 `/api/v1/health` 延迟无显著上升
- [ ] 两包并列挂载互不串台；换包版本后旧缓存不复用
- [ ] 移走瓦片目录时健康探针返回可读原因（并入启动自检「地图引擎」项）
- [ ] 全仓检索业务词零命中；本模块不 import 任何其它模块内部
- [ ] 拔掉外网后地图仍可用（与 `map-2d` 联调）
