## 0. 完成情况总览

> 一句话：**共 36 条需求，全部 ⏳**（本专篇为立项，尚未开工）。
> **本引擎的现状最特殊**：它是十个引擎里**唯一"完全没有实现、且现有代码明确把它写错了位置"**的一个。

**现有资产映射**

| 现有实现 | 位置 | 已有 | 缺什么 |
|---|---|---|---|
| `useMapData()` | `frontend/src/app/useMapData.ts`（33 行） | **应用与地图模块之间唯一的连接点**：把 store 字段**直通**成 `MapData` | **没有任何组图逻辑**：只是把 10 个字段原样映射，不做"这个阶段该显示什么"的判断 |
| `DISPLAY_MODE` 表 | **`webMap/map-2d/src/core/displayMode.ts` L4–13** | 场景×阶段 → 模式名 的硬编码表 | **放错了位置**：这是**业务规则**，却写进地图模块内部（详见下方"关键冲突"） |
| `displayModeState.ts` | `map-2d/src/core/`（83 行） | 手动覆盖优先、场景切换解除覆盖、`availableDisplayModes()` | 机制**可用且正确**，但依赖内置表；`M2-CTRL-09` 标 ⏳ 未完成 |
| `syncDisplayMode()` | 同上 L35–43 | 阶段变化时同步徽标 | 调用方（宿主）缺少权威模式来源 |
| 显示模式取值 | 初稿 §3.6 / 专篇 §2.2 `CAND-MAP-01` | 10 种取值 | 见下方"关键冲突" |
| 图层分组 | `map-2d` `LAYER_GROUPS`（**13 组**，以源码为准） | 分组与独立开关 | **"哪组在哪个模式可见"的映射不存在**（`M2-MZ-01-02` 标 ⏳） |
| 区域/标绘 | `map-2d` 图元（`AreaItem` 等 9 类） | 渲染能力齐备 | **区域命名与坐标数据无来源** |
| 地图工具条随阶段变化 | 初稿 §3.6；`CAND-MAP-02` | 界面已按阶段显示 | **变的是"界面"，不是"引擎"**——没有声明式的工具集配置 |

**关键冲突（必须在开工前裁决 —— 本专篇最重要的发现）**

> `map-2d` 自己的需求文档写着两条**未完成**且**与本引擎直接相关**的条目：
>
> - **`M2-MZ-01-04`**：「显示模式取值清单**必须由宿主提供**；模块只提供'展示一个字符串 + 优先级规则'的能力」
>   验收标准：「**模块内无内置模式名清单**；宿主不提供时显示'未指定'且不报错」→ 状态 **⏳ P1**
> - **`M2-MZ-01-02`**：「'上下文 → 表现'的规则（哪些图层在某上下文下可见）**不得硬编码在模块内**；改为宿主可注入的映射表 + 通用缺省」→ 状态 **⏳ P0**
>
> 但现状是：`map-2d/src/core/displayMode.ts` **内置了一张 `DISPLAY_MODE` 表**（含具体模式名与阶段绑定）。
> 而 `M2-CTRL-08` 却标了 ✅「模块内不含任何具体模式名清单」——**这两条自相矛盾**。
>
> 更关键的是**取值对不上**。三份材料给出三个版本：
>
> | 来源 | T2 | T3 | 缺失的取值 |
> |---|---|---|---|
> | 需求初稿 §3.6（10 种） | （无 T2） | 侦察展开、侦察融合 | 打击确认、引导控制 |
> | `map-2d` 内置表 | **链路拓扑** / **云边端拓扑** | 侦察展开 / **边缘融合态势** | 侦察融合、打击确认 |
> | 技术需求专篇 `CAND-MAP-01` | — | — | — |
>
> **`链路拓扑` / `云边端拓扑` / `边缘融合态势` 这三个取值在需求初稿的 10 种里根本不存在**
> （初稿里"链路拓扑"是 **T2-1 的面板标题**，"云边端拓扑"是 **T2-1 的界面标题**，"边缘融合态势"是 **T3-2 的地图标题**——都不是"显示模式"取值）。
>
> **结论**：这个映射今天放在了错误的模块里，且内容是错的。**`view-composer` 就是它唯一正确的位置。**

## 1. 定位与边界

### 1.1 定位

```
输入（只读）：phase-engine 当前阶段 · 各业务引擎的实体与状态 · mission-baseline 的区域与命名
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│  view-composer（C++，纯声明式，无渲染、无 Web 框架）        │
│  MODE 模式解算 → LAYER 图层组裁决 → TOOL 工具集 →           │
│  DECO 业务标绘 → 输出「组图方案」（声明式）                  │
└──────────────────────┬───────────────────────────────────┘
                       │ 组图方案（纯数据，不含渲染指令）
                       ▼
   宿主适配器（useMapData 的角色）→ MapData → map-2d：画
```

**一句话**：view-composer 回答"**这个阶段地图上该有哪些图层组、哪个工具可用、哪些区域要圈出来、模式徽标该显示什么**"。
它**不画任何东西**（`map-2d` 画）、**不产生业务数据**（只读其它引擎）、**不做面板与导航**（宿主界面壳）。

### 1.2 为什么必须是独立引擎

1. **位置错了**：今天的映射在 `map-2d` 内部，**违反 `map-2d` 自己的 `M2-MZ-01-02` / `M2-MZ-01-04`**（两条都标 ⏳ P0/P1）。这个映射必须有地方放，放宿主就违反 `DISC-04`，所以它必须是一个引擎。
2. **它是唯一允许同时读多个业务引擎的模块**（只读、单向）——这是"适配器文件同时 import 两个包是对的"在业务层的推广（`realtime-hub` README 原话）。
3. **它有两个消费者**：换一套系统，阶段名与图层映射会变，但**"模式 → 图层组"的组图机制相同**。
4. **它是界面一致性的收口点**：初稿 §10.11 记录的"全局框架一致性"问题（语音入口、底部状态条、独立版式）需要一个统一的地方声明。

### 1.3 范围边界

| 做 | 不做 |
|---|---|
| **显示模式解算**：模式清单、`场景+阶段 → 模式` 映射、手动覆盖优先级 | 🚫 不做渲染（`map-2d`）；不 import `map-2d` 内部 |
| **图层组裁决**：模式 → 哪些图层组可见（对齐 `M2-MZ-01-02`） | 🚫 不做图层内的图元数据（来自业务引擎） |
| **工具集声明**：当前阶段允许哪些地图工具 | 🚫 不做工具的实现（量算/绘制在 `map-2d`） |
| **业务标绘**：区域多边形、命名、配色语义、图例分组内容 | 🚫 不做符号绘制（`map-2d` 符号库） |
| **底图选择建议**：当前模式建议哪套底图 | 🚫 不切换底图（宿主调 `map-2d` `basemaps.switch`） |
| 输出**声明式组图方案**（纯数据） | 🚫 不做数据产生、不做落库、不做广播 |
| 独立态势图的模式（第二屏/第三屏） | 🚫 不做版式与路由（宿主界面壳） |

### 1.4 硬约束

| 约束 | 取值 | 依据 |
|---|---|---|
| 输出可被 `map-2d` 消费 | 模式字符串经 `map-2d` 的**手动覆盖**入口注入（`setDisplayModeManual` 语义），徽标只显示宿主传入值 | `M2-CTRL-08`；`map-2d` `displayModeState.ts` |
| 图层组枚举 | MUST 对齐 `map-2d` 的 **13 个**图层分组名（以源码 `LAYER_GROUPS` 为准） | `map-2d` `LAYER_GROUPS` / `LAYER_GROUP_LABELS` |
| 图元形状 | 输出 MUST 可映射到 `map-2d` 的 9 类图元（`area/drone/target/link/track/scan/pulse/cluster/label`） | `map-2d` 接口文档 §3.3 |
| 地图配置 | `GET /api/v1/map/config` 的 `{center, zoom, minZoom, maxZoom, basemap}` 形状**不得破坏** | 契约 §3.1 |
| **禁用三维** | 输出 MUST NOT 含任何三维字段（`terrain` / `3dtiles` / 楼层） | 初稿附录 A/B；`map-2d` §0.3 |
| 模式徽标 | 由宿主提供字符串；模块内含清单的部分 MUST 由本引擎供值 | `M2-MZ-01-04` |
| 语言/构建 | C++17 + CMake ≥ 3.20；仅 `nlohmann/json` | 对齐既有 C++ 模块 |

## 3. 功能需求条目

### 3.1 显示模式解算（VWC-MODE）

> 本域直接落地 `map-2d` 的 `M2-CTRL-08` / `M2-CTRL-09` / `M2-MZ-01-04`。

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| VWC-MODE-01 | **MUST** 模式清单由本引擎提供（模式 key + 显示名 + 所属场景/阶段映射），**MUST NOT 出现在 `map-2d` 或宿主源码里** | 全仓检索模式名（`综合态势` 等）只在 rules 包与引擎测试数据中出现 | ⏳ |
| VWC-MODE-02 | **MUST** 解算 `(场景, 阶段) → 模式`，缺失组合 MUST 返回"未指定"且不报错（对齐 `M2-CTRL-09` 验收） | 给出未声明组合 → 返回未指定，无异常 | ⏳ |
| VWC-MODE-03 | **MUST** 手动覆盖优先且可解除：宿主可指定模式，解除后回落解算值；**场景切换 MUST 自动解除覆盖**（换任务了） | 三种状态（自动/手动/已解除）可查询且行为一致 | ⏳ |
| VWC-MODE-04 | **MUST** 模式取值与需求初稿 10 种对齐；**`链路拓扑`/`云边端拓扑`/`边缘融合态势` 这三个取值 MUST 被裁决**（见 §5 D2、§9 待确认 1） | 输出取值集合有唯一权威定义；界面徽标与该集合一致 | ⏳ |
| VWC-MODE-05 | **MUST** 模式变更可查询"为什么是这个模式"（解算来源：自动 / 手动） | 变更原因可读 | ⏳ |
| VWC-MODE-06 | **SHOULD** 模式列表可枚举（供宿主做下拉，替换 `availableDisplayModes()` 的内置表来源） | 枚举结果与权威定义一致 | ⏳ |

### 3.2 图层组裁决（VWC-LAYER）

> 本域直接落地 `M2-MZ-01-02`（P0 未完成）。

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| VWC-LAYER-01 | **MUST** 提供"模式 → 可见图层组集合"的**可注入映射表**，引擎 MUST NOT 把映射写死在代码里（引擎读规则，规则是数据） | 换一份映射即换可见性；引擎内无图层组与模式的硬绑定 | ⏳ |
| VWC-LAYER-02 | **MUST** 映射缺失时的缺省行为明确：**全部按分组开关显示**（对齐 `M2-MZ-01-02` 验收"未注入映射时全部图元可见"） | 不提供映射时所有组可见，无异常 | ⏳ |
| VWC-LAYER-03 | **MUST** 图层组名 MUST 对齐 `map-2d` 的 13 组枚举（源码为唯一事实），未知组名 MUST 被拒绝并可读 | 传未知组名 → 拒绝并指出 | ⏳ |
| VWC-LAYER-04 | **MUST** 与用户手动开关的关系明确：模式裁决是"默认值"，用户显式开关 MUST 优先（或按可配策略） | 用户关掉某组后切模式，行为符合声明的策略 | ⏳ |
| VWC-LAYER-05 | **SHOULD** 分层叠加顺序建议：模式可声明组的叠放建议顺序 | 输出顺序可被宿主应用 | ⏳ |
| VWC-LAYER-06 | **SHOULD** 图层组透明度建议可随模式配置 | 输出可被宿主应用 | ⏳ |

### 3.3 工具集与控件（VWC-TOOL）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| VWC-TOOL-01 | **MUST** 工具集声明式：每个模式声明可用/禁用/隐藏的地图工具，引擎 MUST NOT 内建工具名与阶段绑定 | 换规则即换工具集 | ⏳ |
| VWC-TOOL-02 | **MUST** 与 `map-2d` 的工具条能力对齐（选择/图层/清屏/全屏/测距/区域/新建/标绘），**未实现的工具 MUST 标为不可用而非显示为可用**（现状 `CAND-MAP-02` 是"占位 disabled"） | 输出明确区分 available / disabled / hidden | ⏳ |
| VWC-TOOL-03 | **MUST** 控件清单：当前模式该开哪些地图控件（指北针/比例尺/缩放/图层开关面板/图例） | 输出可被宿主逐项应用 | ⏳ |
| VWC-TOOL-04 | **SHOULD** 图例内容组织：按模式给出图例分组（威胁等级/目标状态/链路状态/图元类型）的显隐 | 输出与 `M2-CTRL-11` 的四组对齐 | ⏳ |

### 3.4 业务标绘（VWC-DECO）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| VWC-DECO-01 | **MUST** 区域声明式：区域由**数据**给出（key、名称、多边形、配色语义、虚线/实线），引擎 MUST NOT 内建 A/B/C 或区域名 | 换数据即换区域；引擎内无区域名 | ⏳ |
| VWC-DECO-02 | **MUST** 区域状态配色语义可配（如 绿=已完成/黄=复查/红=未搜索），**只输出状态码，不输出颜色值** | 输出为状态码；颜色映射归 `map-2d` 主题 | ⏳ |
| VWC-DECO-03 | **MUST** 标绘随阶段显隐：不同阶段可见的区域/标注集合不同，由规则声明 | 跨阶段切换可见集合正确 | ⏳ |
| VWC-DECO-04 | **MUST** 覆盖范围与扫描扇面：可输出扫描覆盖与已覆盖边界的**参数**（中心、半径/多边形） | 输出可映射到 `ScanItem` / `AreaItem` | ⏳ |
| VWC-DECO-05 | **MUST** 与集群颜色映射解耦：只输出"集群标识"，**颜色/形状归 `map-2d`**（`M2-LAYER-02` 数据驱动渲染） | 输出无颜色值 | ⏳ |
| VWC-DECO-06 | **SHOULD** 标绘模板可复用：一组标绘可命名并存为模板（对齐 `M2-DRAW-15` 样式模板） | 模板名可被图元引用 | ⏳ |

### 3.5 底图建议（VWC-BASE）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| VWC-BASE-01 | **MUST** 按模式/区域给出**建议底图标识**（不切换，只建议） | 输出底图 id；宿主决定是否应用 | ⏳ |
| VWC-BASE-02 | **MUST** 底图标识 MUST 来自 `map-2d` 的可用清单（`basemaps.list()` 语义），**未注册的标识 MUST 不输出** | 输出标识必在可用清单中 | ⏳ |
| VWC-BASE-03 | **MUST** 中心与缩放建议：按场景/区域给出建议视角（center/zoom/minZoom/maxZoom），由规则数据给出 | 输出可被 `map-2d` `config` 消费 | ⏳ |
| VWC-BASE-04 | **SHOULD** 多区域组合：支持"一个场景对应多个瓦片包/区域"的建议 | 输出可含区域标识 | ⏳ |

### 3.6 独立态势图（VWC-VIEW）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|

## 4. 引擎与规则的划分（policies）

| 属引擎（可复用） | 属规则（`policies/mapapp`，项目专属） |
|---|---|
| 模式解算机制、手动覆盖优先级、解除规则 | **10 种模式名与 `(场景,阶段) → 模式` 映射表** |
| 图层组裁决机制与缺省行为 | **模式 → 可见图层组**的映射 |
| 工具集/控件的声明与校验 | **每个模式的工具与控件清单** |
| 标绘的结构与状态码输出 | **区域清单**（A/B/C、核心搜索区、西侧/北侧重点侦察区、高危区）及其坐标、命名、状态配色语义 |
| 底图建议的结构 | **建议底图 id、中心/缩放、区域标识** |
| 独立态势的组图机制 | **两张独立态势的具体内容与版式标志** |
| 校验（未知组名/未知标识拒绝） | **图层组与工具的中文显示名** |

**判据**：引擎公开接口里出现 `综合态势`、`A区`、`西侧重点侦察区`、`复核态势` 即破线（这些是规则数据）。

## 6. 风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | **模式取值三方不一致**（初稿 / `map-2d` 内置表 / 技术需求专篇） | 界面徽标与需求不符，评审时被质疑 | D2 先裁决；D4 由 `map-2d` 按自身条目收敛；本专篇 §9 待确认 1 设为阻塞项 |
| R2 | 在 C++ 引擎里"复制"了 `map-2d` 的图层组枚举语义 | 双份定义漂移 | 枚举名作为**契约**（`map-2d` 接口文档 §7）引用；加一条跨模块一致性验收 |
| R3 | 引擎被写成"通用图层配置系统" | 配置地狱、与 `map-2d` 职责重叠 | 只出**声明式建议**，不做渲染、不做数据源管理 |
| R4 | 组图方案过细（把图元数据也包进来） | 与业务引擎职责重叠，双份数据 | 引擎只出"哪些组可见 + 标绘参数 + 模式"，**实体数据仍由各业务引擎供** |
| R5 | 宿主适配器里又出现模式名硬编码 | 边界回退到今天的状况 | VWC-NFR-01 的验收：适配器源码检索模式名零命中 |
| R6 | 独立态势图被做成"另一套引擎" | 维护两份 | VWC-VIEW-* 复用同一套机制，仅规则不同 |

## 7. 验收清单

- [ ] 空环境 clone → 一条命令构建 → 一条命令跑通验收脚本（退出码 0）
- [ ] 全仓检索模式名、区域名 → 只在规则包与测试数据中出现（引擎源码零命中）
- [ ] 给出未声明的 (场景, 阶段) 组合 → 返回"未指定"，无异常
- [ ] 自动 / 手动 / 已解除 三态行为一致；场景切换自动解除手动覆盖
- [ ] 模式取值集合有唯一权威定义，且与界面徽标一致（含 D2 裁决结果）
- [ ] 换一份"模式 → 图层组"映射即换可见性；不提供映射时全部组可见
- [ ] 传未知图层组名或被拒绝并指出
- [ ] 用户手动关掉某组后切模式，行为符合声明策略
- [ ] 工具集输出区分 available / disabled / hidden，未实现工具标为 disabled
- [ ] 区域输出含状态码但**不含颜色值**；颜色映射由 `map-2d` 完成
- [ ] 标绘随阶段显隐正确
- [ ] 底图建议标识必在 `map-2d` 可用清单中；未注册的不输出
- [ ] 两张独立态势各能产出组图方案，且与平板端数据同源
- [ ] 引擎无渲染、无 IO、无对其它引擎的写调用
- [ ] 宿主适配器（`useMapData` 的角色）源码检索模式名与区域名零命中
- [ ] `map-2d` 源码零改动即可消费本引擎输出
