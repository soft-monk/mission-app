## 1. 全部引擎的共性口径（十条，每份专篇都已写入）

| # | 口径 | 说明 |
|---|---|---|
| 1 | **状态只有两种** | `✅ 已完成` ｜ `⏳ 待完成`。本批全部为 ⏳（立项文档） |
| 2 | **分级用词** | `MUST`（验收必查）/ `SHOULD`（偏离需在决策记录说明）/ `MAY`（可选） |
| 3 | **语言与构建** | C++17 + CMake ≥ 3.20；仅 `nlohmann/json`（内置单头回落） |
| 4 | **不依赖 Web 框架** | 路由由宿主挂载（对齐 `device-ingest` 的 `WITH_HUB=OFF` 做法） |
| 5 | **不依赖 SQL** | 持久化走注入的 `I*Store` 反向接口 |
| 6 | **出口为反向接口** | `IPhaseSink` / `IResourceSink` / `IPlanSink` / `IEntitySink` / `ITopologySink` / `IAlertSink` / `IReportSink` / `ISelfCheckSink` 由宿主实现，用于落库与广播 |
| 7 | **时间可注入** | `IClock` 反向接口，使时序/窗口/迟滞测试完全可复现 |
| 8 | **引擎之间不互相 import** | 只走公开入口；组合只发生在**宿主**与 **`view-composer`** 两个装配点 |
| 9 | **零引擎内业务名词** | 引擎公开接口里 MUST NOT 出现消费者专有名词（见 §3） |
| 10 | **独立交付** | 独立构建、独立示例、独立测试、独立验收脚本（退出码 0/1），空环境 clone 可跑通 |

## 2. 引擎 ↔ 规则（policies）的分界线

**十份专篇的统一模式**：每份都有 §4「引擎与规则的划分」，把"机制"留在引擎、"内容"放进 `policies/mapapp`。

```
mission-engine/（或独立仓）
├─ packages/<engine>/      ← 机制：可复用，第二个消费者零改动
└─ policies/mapapp/        ← 内容：本项目的阶段名、型号、权重、文案、阈值、字段名
```

**判据（一句话）**：
> 引擎公开接口里出现 `T5`、`光电无人机`、`A区`、`云边端`、`93%`、`搜索覆盖率`、`"推荐一个任务模式"` —— **任一个都是破线**。

## 4. 依赖顺序（按"接口能定下来"排，不按重要性）

```
第 0 层（无引擎依赖）
  phase-engine          ← 其余引擎的接口几乎都带"当前阶段"入参，它不定，别人定不下来

第 1 层（依赖第 0 层）
  resource-alloc        ← 被 scoring 读（资源可用量/利用率）
  topology              ← 被 scoring 读（链路稳定度）
  entity-ledger         ← 被 scoring 读（目标优先级）

第 2 层（依赖第 0/1 层）
  scoring               ← 读上面三个的输出作为评分输入（只读，不回写）

第 3 层（聚合与呈现）
  view-composer         ← 唯一允许同时读多个引擎（只读）
  alert-engine          ← 消费各引擎的变更作为规则输入
  report-engine         ← 读全部引擎的快照（字段溯源）
  selfcheck             ← 探针来自各引擎与宿主

全程并行
  llm-provider          ← 只在"转述"时与 scoring 交界（C1/C2 裁决后无耦合）
```

> **为什么 `phase-engine` 必须第一个**：`resource-alloc` / `scoring` / `entity-ledger` / `topology` / `view-composer`
> 的方法签名几乎都带"当前阶段"（`模块仓库清单.md` §6 已指出）。

## 5. 每个引擎的建仓前置清单（与 `模块仓库清单.md` §7 一致）

- [ ] 一句话说清"它单独解决什么问题"，且**不需要提本项目**
- [ ] 公开接口全清单（唯一入口，无内部路径）
- [ ] 公开接口里**检索不到**消费者专有名词（§2 判据）
- [ ] `policies` 与引擎已分离，规则包可替换
- [ ] 反向接口齐备（`I*Sink` / `I*Store` / `IClock` 全部注入）
- [ ] 空环境 clone → 一条命令构建 → 一条命令跑独立示例
- [ ] 自带测试，不依赖宿主数据库与配置
- [ ] 独立验收脚本，退出码 0/1，可进 CI
- [ ] 零跨仓 import（引擎 ↔ 宿主、引擎 ↔ 引擎内部均禁止）
- [ ] 有配套工具（造数 / 夹具 / 压测）
- [ ] `README` 首屏回答：做什么 / 不做什么 / 怎么接 / 怎么验
