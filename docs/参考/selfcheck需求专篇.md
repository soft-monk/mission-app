## 1. 定位与边界

### 1.1 定位

```
各模块注册的探针（map / link / ai / cluster / data / security / position / command …）
   │  探针=纯函数，返回 {status, detail, metric}
   ▼
┌──────────────────────────────────────────────────────────┐
│  selfcheck（C++，无 Web 框架、无 SQL）                     │
│  PROBE 探针注册 → AGG 聚合 → PROG 进度上报 →               │
│  SELF 分项自检 → OVER 状态概览                             │
│                      │                                   │
│                      └──► 出口：ISelfCheckSink（宿主实现）   │
└──────────────────────┬───────────────────────────────────┘
                       │ 自检结果 + 进度（宿主挂 /health）
                       ▼
   启动界面（进度条 + 分项卡片）｜ 底部全局状态条 ｜ 自检不通过的分支
```

**一句话**：selfcheck 回答"**每个模块健康吗、自检五项过不过、状态条该显示什么**"。
它**不做检查实现**（探针由各模块提供）、**不做界面**、**不改阶段**（自检不通过的分支由 `phase-engine` 裁决）。

### 1.2 为什么必须是独立引擎

1. **它是唯一能消除"恒为正常"的地方**：今天的假检查散在 `health()` 一个函数里，没有注册机制。
2. **它是启动界面的唯一数据源**：初稿 §4.1/§4.2 的 5 + 5 + 4 项都从这里出。
3. **它被 `phase-engine` 依赖**：自检不通过是 T0 之前的分支条件（初稿 §10.8）。
4. **它有两个消费者**：换一套系统，探针清单不同，但**注册 + 聚合 + 进度机制相同**。

### 1.3 范围边界

| 做 | 不做 |
|---|---|
| 探针**注册与编排**（注册、超时、并发求值、结果聚合） | 🚫 不做具体检查实现（各模块提供探针） |
| 加载进度上报（各模块进度 → 总进度） | 🚫 不做界面动画（前端渲染） |
| 分项自检编排（一项可含多个子检查） | 🚫 不做自检不通过后的流程推进（`phase-engine`） |
| 全局状态概览聚合（网络/数据链路/定位/安全） | 🚫 不做网络与定位的实际探测实现（由宿主/系统提供） |
| 结果缓存与节流（自检不是每帧都跑） | 🚫 不做告警（自检失败可产生告警，但那归 `alert-engine`） |
| 重检与失败原因可读 | 🚫 不做权限校验 |

### 1.4 硬约束

| 约束 | 取值 | 依据 |
|---|---|---|
| **`/health` 负载形状** | `{status, checkedAt, modules[{key,name,status,detail,metric}], selfCheck[{key,name,sub,status}], systemOverview[{key,name,status,text}], wsClients}` **不得破坏** | 契约 §3.1（前端与验收脚本已依赖） |
| 模块键 | `map` / `link` / `ai` / `cluster` / `data`（5 项，与初稿 §4.1 的 5 个进度卡一一对应） | 契约 §3.1；初稿 §4.1 |

## 3. 功能需求条目

### 3.1 探针注册（SFC-PROBE）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| SFC-PROBE-01 | **MUST** 探针注册机制：任何模块可注册探针（`{key, 名称, 求值函数, 超时, 依赖}`），引擎 MUST NOT 内建任何探针实现 | 新增一个探针无需改引擎代码；引擎内无 `tilesDir` 之类的具体检查 | ⏳ |
| SFC-PROBE-02 | **MUST** 消除占位常量：`aiOk = true`、`position/command/security` 的硬编码 `"normal"`、`systemOverview` 四项常量（`Api.cc` L233/255/257/258/264–267）**MUST 全部改为真实探针** | 拔掉 AI 桥 → `ai` 项变为 fail；拔掉定位 → `position` 变 abnormal | ⏳ |
| SFC-PROBE-03 | **MUST** 探针超时可配：单个探针超时 MUST 只影响该项，MUST NOT 拖垮整次自检 | 故意挂一个不返回的探针 → 该项超时、其余项正常返回 | ⏳ |
| SFC-PROBE-04 | **MUST** 探针求值并行且总时限可配（对齐界面"预计 15~30 秒"） | 5 项并行，总耗时接近最慢项而非各项之和；超时按时返回 | ⏳ |
| SFC-PROBE-05 | **MUST** 探针为纯函数：MUST NOT 有副作用（不改状态、不写库） | 连续求值两次结果一致；无副作用可验证 | ⏳ |
| SFC-PROBE-06 | **SHOULD** 探针分组：支持"一项自检 = 多个子检查"（如"通信链路检测"含卫星/数传/组网三项），子项结果可分别呈现 | 一项含 3 个子检查，结果逐子项可读 | ⏳ |

### 3.2 聚合与负载（SFC-AGG）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| SFC-AGG-01 | **MUST** 输出 `/health` 负载，形状与现状**逐字段一致**（`status/checkedAt/modules/selfCheck/systemOverview/wsClients`） | 与契约 §3.1 的 `data` 结构逐字段比对 | ⏳ |
| SFC-AGG-02 | **MUST** `metric` 为 0–100 整数；部分可用时 MUST 给出中间值（如现状 `link=60`、`cluster=40`、`data=0` 的降级语义保留） | 断掉某能力 → metric 落在约定区间 | ⏳ |
| SFC-AGG-03 | **MUST** `status` 汇总规则显式：整体 `status` 由各模块决定（全 ok → `ok`，有 fail → 可配策略：`degraded` / `fail`） | 策略可配且可复现 | ⏳ |
| SFC-AGG-04 | **MUST** `checkedAt` 为本次自检时刻（不是加载时刻） | 重检后时间更新 | ⏳ |
| SFC-AGG-05 | **MUST** 结果缓存与节流：自检 MUST NOT 每次请求都重跑（可配 TTL）；显式重检 MUST 绕过缓存 | 连续请求命中缓存；【重新检测】触发真实重跑 | ⏳ |
| SFC-AGG-06 | **SHOULD** 历史与趋势：最近 N 次自检结果可查（供排障与"失败项可重检"） | 可读出最近 N 次及其差异 | ⏳ |

### 3.3 加载进度（SFC-PROG）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| SFC-PROG-01 | **MUST** 真实进度上报：各模块 MUST 能上报自己的加载进度（0–100），MUST NOT 用等分假动画 | 全仓检索 `step / 20` 与 `setTimeout(..., 60)` 这类假进度零命中 | ⏳ |
| SFC-PROG-02 | **MUST** 各模块进度目标值由模块自己声明，MUST NOT 在前端写死 `[100,100,100,100,100]` | 前端检索该数组零命中 | ⏳ |
| SFC-PROG-03 | **MUST** 总进度口径显式：等权平均 or 加权（可配） | 换口径可复现 | ⏳ |
| SFC-PROG-04 | **MUST** 进度单调不减（除显式重置），避免界面回退 | 任意序列下进度不倒退 | ⏳ |
| SFC-PROG-05 | **SHOULD** 进度查询为轻量端点（供启动页高频轮询），与全量 `/health` 分离 | 轮询端点响应 ≤ 5 ms | ⏳ |
| SFC-PROG-06 | **SHOULD** 启动完成事件：全部就绪时给出可订阅的完成通知，替代前端"20 步跑完"的判定 | 完成事件只发一次 | ⏳ |

### 3.4 分项自检与概览（SFC-SELF）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| SFC-SELF-01 | **MUST** 五项分项自检的**名称与子说明**由规则提供（文案属规则），引擎 MUST NOT 内置中文文案 | 换规则即换文案；引擎内无 `"卫星链路 / 数传链路 / 组网链路"` | ⏳ |
| SFC-SELF-02 | **MUST** 自检项状态由子检查聚合决定，MUST NOT 硬编码 | 子检查异常 → 该项 abnormal | ⏳ |
| SFC-SELF-03 | **MUST** 自检失败项给出**可读原因与建议**（不是只有 abnormal） | 失败项带原因文本 | ⏳ |
| SFC-SELF-04 | **MUST** 重检：可对单项或全部重新求值，且 MUST 绕过缓存 | 重检后结果可变化 | ⏳ |
| SFC-SELF-05 | **MUST** 状态概览 4 项由探针派生，MUST NOT 硬编码（现状 L264–267 全是常量） | 改变实际状态 → 概览随之变化 | ⏳ |
| SFC-SELF-06 | **SHOULD** 底部状态条第 6 项（AI 决策引擎在线/离线、无人机状态等，初稿 §3.5）同样由探针派生 | 逐项可查 | ⏳ |

### 3.5 非功能性（SFC-NFR）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| SFC-NFR-01 | **MUST** 零外部依赖：无 Web 框架（路由由宿主挂载）、无 SQL（数据来自探针）；不依赖其它引擎内部 | 空环境独立构建；跨仓 import 零命中 | ⏳ |
| SFC-NFR-02 | **MUST** 时间可注入（`IClock`），使超时与缓存 TTL 测试可复现 | 注入假时钟测试通过 | ⏳ |
| SFC-NFR-03 | **MUST** 独立交付：独立构建、独立示例、独立测试、独立验收脚本（退出码 0/1） | 空环境 clone → 一条命令构建 → 一条命令验收 | ⏳ |
| SFC-NFR-04 | **MUST** 探针失败不抛异常：任一探针崩溃 MUST 只影响该项，引擎 MUST NOT 整体失败 | 注入一个会崩的探针 → 其余项正常，该项标 fail | ⏳ |
| SFC-NFR-05 | **MUST** 出口为反向接口：`ISelfCheckSink`（自检完成通知）由宿主实现用于广播 | 引擎内无广播 | ⏳ |
| SFC-NFR-06 | **SHOULD** 性能：全量自检（5 组探针）P95 ≤ 3 s；进度端点在缓存命中时 ≤ 1 ms | 实测达标 | ⏳ |

## 4. 引擎与规则的划分（policies）

| 属引擎（可复用） | 属规则（`policies/mapapp`，项目专属） |
|---|---|
| 探针注册、超时、并行求值、纯函数约束 | **探针清单与其实现**（地图/链路/AI/集群/数据/定位/安全） |
| 聚合、汇总策略、缓存与节流 | **五项自检的中文名称与子说明文案** |
| 进度上报、总进度口径、完成事件 | **模块键与显示名**（地图引擎/通信链路/AI 引擎/集群管理/数据服务） |
| 失败原因的结构与呈现 | **各健康等级的 metric 取值口径**（现状 100/60/40/0） |
| 历史与趋势机制 | **缓存 TTL 与总时限取值** |

**判据**：引擎公开接口里出现 `"瓦片目录已就绪"`、`"卫星链路 / 数传链路 / 组网链路"`、`tilesDir` 即破线。

## 6. 风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 改成真实探针后，演示环境某些项**真的会变红**（如未配 AI Key、无 GPS 硬件） | 现场观感 | 探针分级：区分"未配置"与"故障"，未配置给出中性态而非 fail；并在规则里声明演示环境期望值 |
| R2 | 探针并行求值引入线程 | 复杂性与竞态 | 探针必须纯函数（SFC-PROBE-05）；超时用独立看门狗 |
| R3 | 前端假进度移除后启动页变化太"快"或太"顿" | 观感 | 真实进度上报 + 最短展示时长可配（保底观感） |
| R4 | 引擎被写成"通用健康检查框架" | 配置地狱 | 只支持"探针注册 + 超时 + 聚合 + 进度"，**不做分布式健康、不做告警、不做自动恢复** |
| R5 | 自检耗时长与界面"15~30 秒"文案不符 | 文案误导 | SFC-PROBE-04 总时限可配；文案随实测调整 |
