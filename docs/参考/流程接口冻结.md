## 2. 命令面（冻结）

统一 `POST /api/command`，`code` 取值：`0` 成功 · `1000` 参数/未知 verb · `1003` 前置不满足 · `1004` 未找到 · `1005` 内部不可用（模块/规则未装载）· `1006` 版本不匹配。
**幂等成功**一律 `code=0` + `data.idempotent=true`（不返回 1002；1002 只用于互斥冲突）。

> **命令序（P3 实测补充，前端必须照此实现）**：`alloc.plans` → **`alloc.adopt`（硬前置）** → `alloc.confirm` → `alloc.assign`。
> 直接 `confirm` 会回 `1003`（`data.unmet=["not-adopted"]`，注意细节在 **data** 里）；跳过 adopt/confirm 直接 `assign` 也回 `1003`。
> 另外三个**实测形状**（与最初的设想不同，以前端实测为准）：
> - `alloc.plans` 的 `data.items[]` 是**两层**：`{candidate:{id,name,method,effect,successRate,recommendedHint,clusters[]}, score:{total,rank,recommended,metrics[6]{key,name,raw,unit}}}`；**评分在 `score.total`**；顶层另有 `recommendedId/recommendedPercent/nextId/nextPercent/leadOverNextPercent/reasons[]/notes[]`。
> - `situation.snapshot` 返回 **`overview`**（不是 `systemOverview`）与 **`zones`**（不是"空域通道"单独一段），并带 `notes[]` 说明每一项的来源。
> - `boot.reset` / `mission.reset` 会**清空任务与阶段**（下一次 `flow.enter` 建**新任务**，missionId 递增）——
>   所以"重跑一遍"不需要重启进程；但**必须在浏览器无关的验收脚本里先 reset**，否则 `phase` 会停在上一轮的 T1/T2。
>
> **P4 实测形状（步 6–7，前端按这些写）**：
> - `sim.state`（**事件**）：`{running, speed, simElapsedMs, platforms, emitted}`；倍速改动后事件里的 `speed` 立即变。
> - `topology.evaluate`：链路在 **`data.links[]`**（`{linkId, from, to, state, metrics[{key,last,unit}]}`）；
>   `data.topology` 是**另一个结构**（无脑取它会得到 0 行）。`state` 取值域是 `green/yellow/red`，**只做颜色映射，不自己判级**。
> - `sensor.status`：`coverageRatio`（0–1 有界）与 `coverageUpperBoundRatio`（**上界，不是覆盖率**，≫1）是两套口径，界面 MUST 分开标注；
>   `revisitPeriodMs` 是 `{count,mean,min,max}`（显示 `mean`，另列 min/max/样本数）。
> - `targets.list`：`items[]{id,no,typeKey,typeName,threatBand,threatScore,status,dynamicState,confidence,sources[]}`。
> - `targets.detail`：含 **`declaredActions[]`** —— 可执行动作**以引擎返回的清单为准**（当前规则包是
>   `watch/track/upgrade/strike/reassess`；契约早期写的 `observe` **不存在**，传它会回 1004）。
> - `targets.act`：回执是**双层**（动作结果在 `reply.data.data`）；成功为 `code=0` + `idempotent=true`。
> - `media.channels`：**事件优先**、verb 兜底；通道形状 `{id,name,kind,url|frames,frameIntervalMs}`。
> - 消费 `media-player`（npm 包，Vite 别名指向其**源码**）：它内部用显式 `.ts/.tsx` 后缀 import，
>   所以宿主侧要同时开 `allowImportingTsExtensions`（tsconfig）并挂它那份 `stripTsExtension` 插件（vite.config）。
>
> **P5 实测形状（步 8–9，前端按这些写）**：
> - `strike.plans`：`items[]` 的**M5 四字段在 item 行上**（与 `candidate`/`score` 平级；
>   `template` 里另有一份原文）——不是塞在 `candidate` 里。评分同样在 `score.total`。
> - `guidance.plan` 与最初的设想差别较大：IP 点是**单数 `ipPoint`**；连线在 **`guidance.lines[]`**
>   （每项 `{from,to,lengthM}`，**没有 id/points**）；时间轴是 `timeline:{anchor,items[]}`，
>   段键是 **`arrival`**（不是 `arrive`），每段 `basis` 是 **`{formula,inputs,source}` 对象**，
>   时刻以 `atMs/atText` 为主、部分段另有 `offsetMinutes`。
> - **命令序在步 8/9 之间是反的**：`strike.adopt` 落**步 8**、`strike.confirm` 落**步 9**
>   —— 在步 9 发 `adopt` 会把流程**切回步 8**。步 9 的正确序是"先 `confirm`；回 `1003` 才补 `adopt` 并重试一次"。
> - `strike.confirm` **不自动推进**到步 10（回执里只有 `advance.step`，没有 `toStep`）。
> - `guidance.groups[].members` 是**对象数组**；`membersTotal`（编入平台数）与 `clustersMatched`（匹配集群数）是两个数，别混用。
> - 映射到地图：IP 点用 `MapDraw.add('label'|'symbol')`、引导连线与评估航线用 `MapDraw.set('route')`；
>   坐标**一律取 `guidance.plan` 的返回值**，MUST NOT 前端算/编；离开本屏要自清理这些图元。

## 7. 已知"必须自己保活/自己加锁"的坑（P2 踩过，P4+ 会再遇到）

| 坑 | 现象 | 处置 |
|---|---|---|
| hub 心跳判死 | 只收不发的 WS 连接 **约 4.5 s** 被踢（1.5 s × 3 次心跳未见）；验收脚本采集长过程时"一条都收不全" | 采集器自己按 ~1.2 s 发 `sys.ping` 保活 |
| Node 全局 WebSocket 与 fetch 共用 dispatcher | **先 fetch 再建 WS** → 升级请求被并到 keep-alive 连接上，只来一个 error、永不 open | 脚本里 **先建 WS，再发 HTTP** |
| 引擎线程安全口径不一 | `topology` 全模块无锁、`sim-source` 单写者假设；Drogon handler 跑在多 IO 线程 | 所有引擎调用走 FlowEngine 的一把锁（P3 起的新 verb 必须遵守） |
| React 样式简写 diff | 同一棵树位置切换元素时移除 `inset` 会**连带清掉 `top`**，而"值没变"的 `top` 不会被重设 → 整屏塌成 0 高 | 一律用 `left/right/bottom` 长写；**不要** `inset` 与 `top` 混用 |
| headless 截图 | `backdrop-filter` 在无 GPU 的 headless 下整块面板不参与合成（截图"面板消失"）；新建 target 默认视口可能只有 ~420 px 高 | 面板不用 `backdrop-filter`；脚本先 `Emulation.setDeviceMetricsOverride(1280x800)` |
